# Quorum Edition release operations

The `Quorum-Agent/hermes-agent` repository is the source and update authority
for Quorum Edition. Nous Research remains the upstream Hermes authority; never
publish Quorum artifacts under an upstream URL or imply upstream endorsement.

## Release classes

- A developer preview may be unsigned. Its GitHub prerelease title and notes
  must say that operating-system trust dialogs are expected.
- A stable desktop release must be signed on Windows and macOS. macOS artifacts
  must also be notarized. If credentials are absent or signing/notarization
  fails, the workflow must fail or publish a prerelease—never silently label
  unsigned output stable.
- Linux packages are checksum-covered; repository signing is a separate future
  distribution channel and is not implied by a `.deb` artifact.

## Required release outputs

The release workflow builds on native runners and uploads:

- Windows x64 NSIS installer (`Quorum-*.exe`)
- Linux x64 Debian package (`Quorum-*.deb`)
- macOS x64 and arm64 disk images (`Quorum-*.dmg`)
- `quorum-plugin.zip` for existing stock-Hermes users
- `SHA256SUMS` covering every published payload
- build/provenance metadata generated by GitHub Actions

The Electron artifact name also includes version, operating system, and
architecture so different matrix outputs cannot overwrite one another.

## Preflight checklist

1. Rebase or merge the current upstream Hermes `main`, resolve deliberately,
   and record the upstream commit in the release notes.
2. Run the canonical Python test wrapper, routing-engine tests, desktop
   typecheck/lint/unit tests, Companion reproducibility test, and installer
   syntax tests.
3. Confirm `git diff --check`, the lockfiles, pinned GitHub Actions, secret
   scanning, and dependency scans are clean.
4. Build the Companion twice and compare hashes.
5. Run clean install/update/uninstall smoke tests on each target OS. Confirm
   Quorum uses `.quorum`/`%LOCALAPPDATA%\quorum` and leaves Hermes state alone.
6. Confirm the policy guard still blocks a private cloud request before the
   provider callback and blocks recognized sensitive arguments before a
   network-capable tool callback.
7. Verify signing identities and notarization credentials on protected GitHub
   environments before choosing a stable release.

## Publishing

Use the repository's Quorum release workflow. Prefer a versioned tag created
from a protected `main` commit; do not upload binaries built from an uncommitted
worktree. Review generated checksums and release notes before promoting a
prerelease to stable.

Stable jobs are bound to the protected `quorum-release` GitHub environment;
configure required reviewers and place Windows, Apple, and GPG signing secrets
there. Unsigned manual builds use the separate `quorum-preview` environment and
produce explicitly labeled developer-preview artifacts. Tagged payloads receive
GitHub/Sigstore build-provenance attestations in addition to the detached GPG
signature over `SHA256SUMS`.

After publication, install each artifact from the release page, verify its
checksum, launch it, complete first-run setup, exercise one permitted local
request and one expected policy block, then test the in-app update authority.
Keep the previous release available for rollback.
